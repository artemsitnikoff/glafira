# 12 — Заявки на подбор

## Зачем и почему НЕ отдельный раздел
Заявка — это ещё-не-вакансия: менеджер описывает, кто нужен, рекрутер уточняет, открывает вакансию, наймом закрывает заявку. Это один жизненный цикл: **Заявка → Вакансия → Найм → Архив**. Поэтому заявки живут внутри раздела «Вакансии», а не отдельным пунктом меню:

- в подсписке «Вакансии» закреплённая строка **«Заявки»** сверху (симметрично «Архиву» снизу): до / сейчас / после;
- бейдж `+N` новых на строке «Заявки» и пип на пункте «Вакансии» в свёрнутом меню;
- вакансия, созданная из заявки, несёт в шапке чип **«по заявке №N»** (клик — назад в заявку);
- в карточке заявки в подборе — живой прогресс связанной вакансии (кандидаты, новые, нанято X из Y).

## Статусы и переходы
| Статус | Кто/что переводит | Действия рекрутера |
|---|---|---|
| **Новая** | менеджер подал заявку (форма по ссылке) или рекрутер внёс вручную | Взять в работу · Отклонить · вопрос в тред (автоматически берёт в работу) |
| **В работе** | рекрутер взял заявку | Создать вакансию (форма предзаполнена из заявки) · Отклонить · уточнения с заказчиком |
| **В подборе** | создана вакансия — заявка связана с ней | Открыть вакансию; прогресс «нанято X из Y» подтягивается из воронки |
| **Закрыта** | автоматически, когда нанято Y из Y (или вручную) | — (итог: кто нанят, срок найма) |
| **Отклонена** | рекрутер с обязательной причиной (видна менеджеру) | Вернуть в работу |

## Экраны (в дизайне раздела «Кандидаты»)
1. **Список** (`Вакансии → Заявки`): шапка с действиями («Ссылка на форму», «Воронка» → настройки, «Новая заявка»), воронка-чипы этапов со счётчиками (Все | Новая → В работе → В подборе → ✓Закрыта ‖ ✕Отклонена) и поиск — как у кандидатов. Ниже — КАРТОЧКИ заявок на сером фоне (не таблица): цветной кант этапа слева, аватар заказчика, три строки (№ + должность + 🔥 / заказчик · роль / отдел · город), мини-колонки с подписями Позиции / Срок / Подана (даты), справа бейдж этапа (+прогресс «нанято X из Y» у «В подборе»).
2. **Панель заявки** — открывается поверх правых колонок (как карточка кандидата): тулбар «Перевести ▾» / «Отклонить ▾ (причина)» / «Создать вакансию» (или «Открыть вакансию» / «Вернуть в работу»), Б24-полоса этапов для перевода в один клик, ниже — описание от менеджера, тред уточнений, параметры, связанная вакансия (или итог / причина отклонения), история.
3. **Перевод по воронке**: клик по шагу полосы или пункту «Перевести». Перевод в «В подборе» без вакансии = запуск создания вакансии (предзаполненный мастер); «Закрыта» вручную фиксирует итог; «Отклонить» требует причину.
4. **Новая заявка** — отдельная страница в шелле мастера вакансии (крошки «Заявки / Новая заявка», Отмена/Создать): кто нужен, заказчик, отдел, позиции, город, срок, вилка, приоритет, описание.
5. **Создание вакансии из заявки**: мастер предзаполнен из заявки; после создания заявка → «В подборе», событие в историю, панель заявки снова открыта со связанной вакансией.

## Модель данных
```
Request {
  id, num,                 // сквозной номер
  title, desc,             // кто нужен (кратко, от менеджера)
  author, role, dept,      // заказчик
  positions, city, deadline, salaryFrom?, salaryTo?,
  priority: normal|high,
  status: new|work|sourcing|done|rejected,
  vacancyId?,              // связь 1:1 с вакансией (с момента sourcing)
  hired?,                  // из воронки вакансии
  rejectReason?, closedNote?,
  comments[] {side: manager|recruiter, author, time, text},
  history[]  {t, label}
}
```

## Роль «Нанимающий менеджер» и ссылка-форма
Два канала подачи: роль в Глафире (основной) и внешняя форма по длинной непубличной ссылке (для менеджеров без аккаунта; макет `Форма заявки - менеджер.html`). Заявки с формы помечаются чипом «по ссылке-форме» в карточке (поле `via: form|cabinet|manual`, пример — №20); генерация/ротация ссылки — на беке.
Роль в Глафире (Настройки → Права доступа):
- Менеджер видит только раздел «Мои заявки» (единственный пункт в сайдбаре) и только СВОИ заявки.
- Может: подать заявку (та же страница-форма, заказчик зафиксирован = он сам), следить за этапом (воронка-чипы, БЗФ-полоса в карточке — read-only), отвечать в треде уточнений, видеть прогресс связанной вакансии (цифры, без перехода) и историю.
- Не может: переводить этапы, отклонять, создавать вакансии, видеть чужие заявки и остальные разделы CRM. В тулбаре карточки вместо действий — плашка «Заявка у рекрутинга…».
- В прототипе: переключатель «Смотреть как: Рекрутер / Нанимающий менеджер (Павел Гусев)» в Tweaks; данные общие — вопрос менеджера сразу виден рекрутеру.

## Настройки → «Воронка заявок»
Этапы воронки заявок редактируются админом в Настройках (отдельный подраздел): первый («Новая»), системный («В подборе») и финальные закреплены; между ними можно добавлять свои (например, «На согласовании»). Там же правила-автоматика: автозакрытие при найме всех позиций, «вопрос переводит в работу», уведомления менеджеру при смене этапа.

## Правила
- Заявка ≠ вакансия: до «В подборе» вакансии не существует; удаление/закрытие вакансии не удаляет заявку (история сохраняется).
- Автозакрытие: `hired == positions` → статус «Закрыта», событие в историю, уведомление менеджеру.
- Вопрос в треде из статуса «Новая» автоматически переводит в «В работе» (вопрос = работа началась).
- Отклонение требует причину; отклонённую можно вернуть в работу.
- Счётчик в сайдбаре — активные заявки (new + work + sourcing); бейдж `+N` — только новые.

## Демо-ограничения прототипа
- «Создать вакансию» из любой заявки связывает с демо-вакансией `fe` (в проде — реально созданная).
- Форма менеджера — ролевой режим внутри прототипа (тумблер в Tweaks); внешняя ссылка-форма — отдельный макет `Форма заявки - менеджер.html`, кнопка «Ссылка на форму» мокает копирование.
- Прогресс найма замокан (`hired`), в проде — из этапа «Оффер принят» воронки.

## Вне скоупа (обсудить)
- Согласование заявки цепочкой (менеджер → директор → HRD) — статус «На согласовании» перед «Новая».
- SLA-таймеры на статусы и эскалации.
- Несколько вакансий по одной заявке (сейчас 1:1).
