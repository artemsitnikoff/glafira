# v1.9.0 — Онлайн-подписание согласия ПдН кандидатом (2026-09-23)

Заменил заглушку запроса согласия на РЕАЛЬНЫЙ онлайн-флоу: кандидат получает ссылку,
открывает публичную страницу с текстом согласия и подписывает его. Как только статус
согласия становится `signed`, consent-гейт 152-ФЗ (верификация/скоринг/поиск по базе)
открывается сам — гейт-логику не трогали.

## Бэкенд
- **Модель/миграция** (`f1a2b3c4d5e6`, down_revision `e7f8a9b0c1d2`, одна голова): в
  `consents` добавлены `token` (секрет ссылки), `expires_at`, `signed_ip`, `signed_by`
  (`candidate`|`recruiter`), `consent_text` (снимок подписанного текста — 152-ФЗ). Partial
  unique-индекс `uq_consents_token WHERE token IS NOT NULL` (старые записи без токена не
  конфликтуют).
- **Текст согласия** — `build_consent_text(ФИО, компания)` + дефолтный шаблон
  (`_CONSENT_TEXT_TEMPLATE`). ⚠️ Дефолт помечен как подлежащий правке юристом заказчика
  (позже вынесем в настройку). Снимок сохраняется в момент запроса.
- **`request_consent` переписан**: генерит `token`/`expires_at` (14 дней)/`consent_text`,
  строит ссылку `{FRONTEND_BASE_URL}/consent/{token}` и ДОСТАВЛЯЕТ её кандидату —
  явным `channel` или авто-выбором (email → telegram → hh). Email — брендированное письмо
  (`render_simple_email` + `send_email`, кнопка «Подписать согласие»); чат-каналы — через
  `send_message` (реальная отправка). Честность: сбой доставки → `delivered:false` +
  `delivery_error`, согласие всё равно создано, ссылка возвращается рекрутёру. Старый
  плейсхолдер-Message «ссылку: [auto-generated]» удалён.
- **Публичный роутер** `api/v1/public_consent.py` (prefix `/public`, БЕЗ авторизации,
  rate-limit 30/60с per IP:token, company_id ТОЛЬКО из токена):
  - `GET /public/consent/{token}` → `{company_name, candidate_name, consent_text, status,
    expires_at, can_sign, already_signed, expired}`. PII-минимум (имя — да; телефон/email/id
    — нет). Неизвестный токен → 404; истёкший → 200 с `expired:true`.
  - `POST /public/consent/{token}/sign` → атомарный `pending→signed`, `signed_ip` из
    X-Forwarded-For, `signed_by=candidate`, audit `sign_consent` (`actor_type=system`).
    Идемпотентно; revoked → 400; истёкший → 410.
- `confirm-signed` (рекрутёр) теперь пишет `signed_by=recruiter` + снимок текста;
  auth-путь кандидата — `signed_by=candidate`.

## Тесты (`tests/test_consents.py`, не прогонялись локально — рантайма нет)
Генерация token/expires/consent_text + доставка (мок), честный `delivered:false` при
неудаче, публичный GET без лишней PII, sign выставляет `signed_ip`/`signed_by`,
идемпотентность, истёкший токен не подписывает, company_id только из токена, гейт
`verify_candidate` открывается после подписи, RBAC менеджера.
