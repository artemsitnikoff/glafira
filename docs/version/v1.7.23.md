# v1.7.23 — Merge-джоб склейки накопленных дублей кандидатов (пункт 2 дедупа) (2026-08-30)

Разовый CLI-джоб, который склеивает УЖЕ накопленные дубли кандидатов в одну «золотую»
запись. Пункт 1 (перекрытие «крана» на импорте hh — новые отклики не плодят дубль) сделан
в v1.7.22; это пункт 2 — чистка того, что накопилось до фикса. Джоб **инертный**: по
умолчанию DRY-RUN, ничего не пишет; в cron не добавляется; запуск ручной.

## Что добавлено
- **`app/services/candidate_merge.py`** — чистый сервис (тестируемый, без ввода-вывода):
  - `compute_components(candidates)` — union-find по СИЛЬНЫМ рёбрам одной компании
    (пара сильная при `phone AND email` / `phone AND last_name` / `email AND last_name`;
    phone = последние 10 цифр, email = lower/trim, фамилия = lower/trim + снятие префикса
    потока `023-`). Компоненты размера ≥2 → авто-мерж (Tier-1). Слабые связи (общий
    телефон/email, но разные ФИО и email) НЕ мержатся → REVIEW-список (Tier-2).
  - `merge_component(session, company_id, member_ids)` — детерминированный мерж одного
    компонента: выбор survivor (employee → богатейший → старейший → меньший id), перенос
    ВСЕХ детей (17 FK-таблиц) с обработкой уник-констрейнтов (candidate_tags, embeddings,
    message_reads, ai_evaluations, talantix-комментарии), разрешение коллизии «оба на
    одной вакансии» (побеждает самый продвинутый этап; дети проигравшей заявки → на
    winner ДО её удаления; `hh_negotiation_id` → `extra['hh_seen_nids']`), дозаполнение
    пустых полей survivor, soft-delete проигравших (`deleted_at`/`duplicate_of`/
    `extra['merged_into']`), `audit_log` (`action='candidates_merged'`, `actor_type='system'`).
    НЕ коммитит — транзакцией управляет CLI. Идемпотентно (живых членов <2 → no-op).
- **`app/jobs/merge_duplicate_candidates.py`** — CLI-обёртка: режимы `--execute` (без него
  DRY-RUN, гарантированно ноль записей), `--company <uuid>`, `--limit N`, `--include-review`;
  savepoint на компонент (сбой одного не валит остальные), commit пачками; печать отчёта по
  компаниям (компонентов слито, кандидатов в утиль, заявок перенесено, коллизий разрешено +
  какой этап победил, Tier-2 review).
- **`tests/test_candidate_merge.py`** — 8 юнит-тестов сервиса (простой мерж, коллизия заявок,
  survivor-employee, слабое ребро→review, уник candidate_tags, изоляция по компании,
  идемпотентность, секции резюме reparent/без дублей).

## Границы / безопасность
- Всё строго company-scoped (§2.3); изменяющее действие → `audit_log` (§2.2).
- Миграций НЕТ — используются существующие поля (`candidates.deleted_at`/`duplicate_of`/`extra`).
- Спорные (слабые) пары автоматически НЕ трогаются — только на глазной просмотр.
- Локально не прогонялось (нет рантайма) — только `py_compile`; pytest — на VPS.

## Запуск (VPS, разово, руками)
```
# проба:
docker compose -f docker-compose.prod.yml run --rm backend \
  python -m app.jobs.merge_duplicate_candidates 2>&1 | tee -a merge-dry.log
# применить (ПРЕДВАРИТЕЛЬНО — бэкап БД scripts/backup_all.sh):
docker compose -f docker-compose.prod.yml run --rm backend \
  python -m app.jobs.merge_duplicate_candidates --execute 2>&1 | tee -a merge.log
# тесты:
docker compose -f docker-compose.prod.yml run --rm backend pytest tests/test_candidate_merge.py -q
```
