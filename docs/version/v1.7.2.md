# v1.7.2 — Talantix превью: честное «N+» при упоре в кап (2026-08-15)

Фикс-форвард к v1.7.0/1.7.1. Жалоба заказчика: превью показало «10 000 Всего строк»,
а в базе Talantix 49 683 кандидата — плоское «10 000» дискредитирует реальный объём.

Причина: превью перечисляет `person_ids` курсором с капом `TALANTIX_PREVIEW_MAX_PAGES=200`
страниц × 50 = **10 000** id (защита от таймаута на большой базе). Когда база больше —
курсор упирается в кап, но UI рисовал ровное «10 000», будто это весь объём.

- **Бэк** (`preview_talantix_import`): в `summary` добавлен флаг
  `total_capped = total >= TALANTIX_PREVIEW_MAX_PAGES * 50` (True → перечисление упёрлось
  в кап, реальная база БОЛЬШЕ показанного). Флаг ставит ТОЛЬКО превью Talantix.
- **Фронт** (`ImpStepPreview`): при `summary.total_capped` к числам «Всего строк /
  Новых / Дублей» дописывается «+» → «10 000+ / 5 000+ / 5 000+». Компонент общий с
  Excel/Поток — там флаг не приходит (undefined) → «+» не появляется, их вид не тронут.
- Сам импорт капом превью не ограничен: `TALANTIX_IMPORT_MAX_PAGES=4000` (до 200k),
  джоб идемпотентен и докачивается — качает всю базу, а не первые 10k.
- Комментарии подтверждены: импортируются в блок «Комментарии» карточки
  (`Comment source='talantix'`, автор/дата ОРИГИНАЛА, пилюля «Talantix», read-only).

Файлы: `backend/app/services/candidate_import.py`,
`frontend/src/pages/candidates/ImportCandidatesWizard.tsx`,
`frontend/src/api/hooks/useCandidateImport.ts`.
