# v1.11.1 — ФССП: перенастройка клиента под api-cloud.ru (2026-09-29)

Провайдер ФССП оказался **api-cloud.ru**, а клиент v1.11.0 был построен под parser-api.com → любой ключ давал «Invalid access key» / провайдер не отвечал в ожидаемом формате.

- **Определён реальный провайдер** по списку активных модулей клиента (`fssp`, `fssp_search`, `fssp_osp`, `fssp_alim`, `nalog_bo/inn/egrul`, `mvd_wanted`, `sudrf_custom`, `fines`) — это api-cloud.ru-семейство.
- **`services/fssp.py` перенастроен на контракт api-cloud:** `GET {FSSP_API_BASE}/fssp.php?type=physical&token=…&lastname=…&firstname=…&secondname=…&birthdate=дд.мм.гггг&region=…`. Успех = `status==200`, записи в `records`. Ошибка провайдера приходит с HTTP 200, но телом `{"error":"…","message":"…"}` (напр. `TOKEN_NOT_REGISTERED_IN_THE_SYSTEM`) → `None` (**не «чисто»**, §0). Маппинг записей расширен (`process_title`/`debtor_name`/`process_subject`/…), сырьё целиком в `raw`.
- **`FSSP_API_BASE` дефолт → `https://api-cloud.ru/api`** (в env — на случай клона/реселлера api-cloud с тем же API, но своим токеном).
- **Тесты обновлены** под контракт api-cloud (`status:200`/`records`; `TOKEN_NOT_REGISTERED`→None; `token/type/lastname/firstname/birthdate/secondname` в query). Блочные тесты (мокают `search_enforcement`) — контракт-агностик, не тронуты.
- **Без изменений в гарантиях:** token-gated + consent-gated. Пусто `FSSP_API_KEY` → блок «Исполнительные производства» = честная заглушка, ФИО/ДР наружу не уходят. Ключ на сервере по-прежнему НЕ задан (предоставленный `27c5…` api-cloud.ru не признаёт — `TOKEN_NOT_REGISTERED`; ждём рабочий токен / точный домен кабинета).
