# v1.7.9 — Хабр Карьера: диагностические логи синка откликов (2026-08-20)

Жалоба: вакансия привязана к Хабру, но откликов нет — админка пишет
«Импортировано: 0, пропущено: 0, проверено вакансий: 1». `poll_habr_responses_now`
при пустом ответе молча `break`, логов почти не было — непонятно, почему 0.

Схема ответа Хабра `/responses` «подтверждена докой», но на живом токене публично
не пинилась (как было с Talantix — реальный ответ может отличаться от доки). Обложил
логами по образцу hh (только форма/счётчики, БЕЗ PII):
- **client.get_vacancy_responses**: логирует URL, HTTP-статус, `top-keys` ответа,
  число `responses` (и «НЕ-список», если ключ другой), `pagination`.
- **client.get_employer_vacancies**: число вакансий + их id — сверить с привязанным
  `habr_vacancy_id`.
- **sync.poll_habr_responses_now**: старт (сколько привязанных вакансий + их
  habr_vacancy_ids), per-vacancy id, счётчик откликов на страницу, а при 0 —
  **сырую структуру ответа** (обрезана; PII нет, откликов ноль) — чтобы запиннить
  схему, если ключ откликов НЕ `responses`. Финальный tally.

Только логирование — поведение не менялось. После деплоя: нажать «проверить» в
админке и `docker compose logs backend | grep habr` — видно реальную форму ответа.
