# v1.9.1 — Фронт онлайн-подписания согласия ПдН (2026-09-23)

Фронтовая надстройка над бэкендом v1.9.0: публичная страница подписания кандидатом +
UI рекрутёра со ссылкой и статусом доставки. Гейт 152-ФЗ открывается сам после подписи —
логику гейта не трогали.

## Публичная страница `/consent/:token` (БЕЗ авторизации)
- `pages/public/ConsentPage.tsx` + `ConsentPage.css` (по образцу `ApplyPage`/`SchedulePage`:
  `publicClient` → `/public/...`, брендовая шапка с компанией из токена, self-import CSS,
  scoped-классы `.cns-*`, только реальные токены).
- На маунте `GET /public/consent/{token}`. Состояния: загрузка → 404/ошибка «Ссылка
  недействительна» → `expired` «Срок действия ссылки истёк» → `already_signed`/`status='signed'`
  «Согласие уже подписано ✓» → `can_sign` — брендовая шапка, весь `consent_text`
  (`white-space: pre-line`), имя кандидата, чекбокс «даю согласие» (кнопка «Подписать»
  активна только при галочке) → `POST /public/consent/{token}/sign` → «Спасибо! Согласие
  подписано ✓» (+ дата). Ошибки из конверта: 410 истёк / 400 отозвано / 429 слишком часто.
- Роут `/consent/:token` в `App.tsx` — вне `AppLayout`/авторизации, lazy, рядом с
  `/schedule`, `/apply`, `/test`.

## UI рекрутёра (таб Верификация)
- `useRequestConsent` (`api/mutations/candidateDetail.ts`): тип ответа расширен полями
  `link/delivered/delivery_channel/delivery_error/signed_by/expires_at` (локальный тип +
  as-cast, openapi отстаёт). onSuccess инвалидирует ключ `['candidates', id, 'consent']`.
- Новый хук `useConsentStatus` (`api/hooks/useConsent.ts`) — `GET /candidates/{id}/consent`;
  локальный тип `ConsentStatus` (с `signed_by`), 404 NOT_FOUND → `null`, включён только
  пока гейт закрыт.
- `VerificationTab`: после «Запросить ПдН» — результат в блоке согласия. `delivered:true` →
  «Ссылка отправлена кандидату ({канал})» + сама ссылка с кнопкой «Скопировать»;
  `delivered:false` → честно «Не удалось отправить автоматически[: причина]. Скопируйте
  ссылку…» + ссылка + «Скопировать». Ссылка показывается всегда. Когда `consentStatus`
  = signed, а `has_pdn` ещё не подтянулся → «Согласие получено · Подписано
  кандидатом/рекрутёром {дата}» вместо кнопок запроса. Кнопка «ПдН подписан»
  (confirm-signed) не тронута. Скоуплённый CSS `.consent-link-*` в `CandidateDetail.css`.
- `CandidatePoolDetailPage`/`CandidateToolbar` — не тронуты, компилируются на новом типе
  ответа (ответ там игнорируется).
