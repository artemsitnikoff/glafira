# v1.10.0 — Формат занятости вакансии + учёт локации в AI-скоринге (2026-09-28)

Бэкенд. У вакансии появилось свойство **«Формат занятости» `work_format`** — одно из
`office` | `remote` | `hybrid` (опционально, nullable). Оно влияет на AI-скоринг: задаёт,
насколько локация кандидата и готовность к переезду важны для соответствия.

## Что сделано
- **Модель `Vacancy`:** новая колонка `work_format` (`String(20)`, nullable), рядом с
  `employment_type`. ⚠️ БЕЗ `CheckConstraint` на значения — валидация в Pydantic (Literal),
  чтобы не повторять инцидент с `check_funnel_template` (500 при создании вакансии).
- **Миграция `a2c4e6f8b0d1`** (down_revision `f1a2b3c4d5e6`, одна голова) — add column
  nullable, downgrade drop column.
- **Схемы `VacancyCreate` / `VacancyUpdate` / `VacancyDetail`:**
  `work_format: Literal["office","remote","hybrid"] | None = None`. Некорректное значение
  → **422** (Pydantic), не 500 и не молчаливое сохранение.
- **Сервис:** персист в `create_vacancy` (конструктор + audit-dict), `update_vacancy`
  (`if ... is not None` — выставляется, но не затирается при отсутствии в PATCH),
  `duplicate_vacancy` (копируется в новую вакансию).
- **Скоринг (главное):** хелпер `_work_format_line(vacancy)` в `services/glafira/scoring.py`
  добавляет в промпт строку про формат работы + инструкцию учёта в весах:
  - `office` — присутствие в городе обязательно, локация/готовность к переезду ВАЖНЫ
    (иногородний без готовности к переезду — существенный минус к соответствию);
  - `remote` — локация кандидата не важна, не снижать оценку за город/регион;
  - `hybrid` — локация важна умеренно (близость/готовность к переезду предпочтительны, не критично);
  - не указан — нейтрально.
  Хелпер применён в ОБОИХ путях построения промпта: инлайн `score_resume_dict` (умный подбор)
  и через новый плейсхолдер `{work_format_line}` в `SCORING_USER_TEMPLATE` (`score_candidate`).
  **Строгий JSON-контракт ответа скоринга не изменён — правится только текст промпта.**

## Тесты (backend/tests/test_vacancies.py)
create/update вакансии с `work_format` сохраняет и отдаёт; без него → null; PATCH другого
поля не затирает; невалидное значение (`foo`/`onsite`) → 422; юнит хелпера `_work_format_line`
на office/remote/hybrid/None/пусто. (Прогон — на VPS: локального рантайма нет.)

## Контракт для фронта
Поле `work_format` в `VacancyCreate` / `VacancyUpdate` / `VacancyDetail`:
значения `"office"` | `"remote"` | `"hybrid"` | `null`. Опционально (по умолчанию `null`).
Некорректное значение → 422.
