# v1.11.0 — Реальная проверка ФССП через parser-api (token-gated) (2026-09-29)

Блок «Исполнительные производства» (ФССП) в верификации кандидата стал реальной
проверкой вместо честной заглушки. Официальный API ФССП закрыт → используем стороннего
провайдера **parser-api.com** (синхронный поиск по банку данных ИП, бесплатный тариф 200/мес).

- **Config:** `FSSP_API_KEY` (env, пусто → интеграция ВЫКЛЮЧЕНА, блок остаётся заглушкой
  «Не подключено» как раньше) + `FSSP_API_BASE` (env, дефолт `https://parser-api.com/parser/fssp_api`
  — сменить провайдера без правки кода).
- **Клиент `services/fssp.py`:** `search_enforcement(last_name, first_name, patronymic, birth_date, region_id=None)`
  — один GET `…/search_fiz` (httpx, таймаут 20с). Дата рождения ОБЯЗАТЕЛЬНА провайдером
  (формат дд.мм.ГГГГ). Проверяет `done==1`, парсит записи ИП в нормализованные словари
  (исходник целиком в `raw`). Graceful: нет ключа / нет ДР / сеть / `done!=1` / 403/400 → `None`.
  ⚠️ `None` = «не удалось проверить» (НЕ «чисто»), `[]` = «провайдер отработал, ИП не найдено».
- **verify.py (заменён ТОЛЬКО блок `fssp`, inn/bankruptcy/registries/alimony не тронуты):**
  нет ключа → заглушка; ключ есть, но у кандидата нет даты рождения → честный `info`
  «Нужна дата рождения»; ключ + ДР → синхронный вызов провайдера рядом с DaData-контактами.
  Найдены ИП → status **`warn`** (ВНИМАНИЕ, не вердикт) + список `data.items` + обязательная
  плашка «Возможные совпадения по ФИО и ДР… возможен однофамилец… НЕ подтверждённая
  задолженность». 0 ИП → `clean`. Сбой/`None` → `info` «Не удалось проверить (ФССП недоступна)»,
  НЕ «чисто» (§0 — молчаливый обман в HR-решениях критичен). `is_mock=False`, аудит/Event
  верификации не изменены (§2.2 цел).
- **Без миграции:** результат кладётся в существующее JSONB-поле `verifications.blocks`.
- **Тесты:** `tests/test_fssp_verification.py` (клиент: dob-формат/парсинг/done!=1/403/таймаут/нет
  ключа/нет ДР → None; блок: заглушка без ключа, «нужна ДР», warn+плашка, clean при 0,
  честный «не удалось» при None; интеграция в verify_candidate + overall-статус).

⚠️ **Операционно (заказчик, на VPS):** получить бесплатный ключ на parser-api.com и задать
`FSSP_API_KEY` в `.env`; при первом живом вызове сверить форму ответа провайдера (ключ
списка `records`, имена полей записи ИП) по info-логу `[fssp] done=1 keys=…` — маппинг полей
защитный, но исходник сохраняется в `raw`. Гейт согласия ПдН (152-ФЗ) уже есть — вся
верификация под подписанным согласием.
