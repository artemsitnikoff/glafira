# v1.11.3 — ФССП: правильный маппинг полей parser-api + вывод списка ИП в UI (2026-09-29)

Живой вызов подтвердил: интеграция тянет **реальные исполнительные производства** (тест «Иванов Иван, 1980» → 11 ИП с суммами/приставами). Но нормализованные поля выходили пустыми — parser-api отдаёт `debtor_name`/`process_title`/`subjects[]`/`officer_name`/`department_title`/`stop_*`, а не имена, которые были заложены наугад.

- **Бек (`services/fssp.py::_normalize_record`)** переписан под реальную форму parser-api (запинена на живом ключе):
  - `subjects` — список: title'ы (кроме метки «Общая сумма задолженности») → **предмет**, значение `sum` → **сумма** (отдельно);
  - `stop_date`/`stop_reason` → **статус ИП** («Окончено …» / «На исполнении»);
  - телефон пристава (`officer_phones[0]`) добавляется к `officer_name`;
  - старые ключи (`name`/`exe_production`/…) оставлены как фолбэк, сырьё целиком — в `raw`. +2 теста реальной формы.
- **Фронт (`VerificationTab.tsx::renderFsspItems`)** — на каждое производство карточка (номер ИП / должник / предмет / сумма ₽ / статус / отдел / пристав) + обязательная плашка про однофамильца; info-состояния (Не подключено / Нужна дата рождения / Не найдено / Не удалось проверить) — статус + примечание. Переиспользованы существующие классы `vf-group`/`vf-kv`, нового CSS нет.
- **Операционно:** блок ФССП реально работает при (1) подписанном ПдН и (2) заполненной **дате рождения** кандидата. Остальные госреестры (ИНН/ЕФРСБ/Росреестр/алименты) — по-прежнему честные заглушки «в разработке».
