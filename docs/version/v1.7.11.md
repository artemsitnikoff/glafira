# v1.7.11 — Хабр: верный base URL API (был потерян /api → все запросы 404) (2026-08-20)

Продолжение разбора «откликов 0». После фикса id (v1.7.10) запрос всё равно давал
**404 Not Found** — и не только `/responses`, но и список вакансий `/vacancies`.

**Причина (вскрыта живым пробингом кандидатов base-path на токене работодателя):**
`HABR_API_BASE` был зашит `https://career.habr.com/v1/integrations`, а верный путь —
`https://career.habr.com/**api**/v1/integrations` (потерян префикс `/api/`). Проверка:
```
200  https://career.habr.com/api/v1/integrations/vacancies → {"vacancies":[{"id":1000168230,"title":"Product Engineer…
404  https://career.habr.com/v1/integrations/vacancies
```
id `1000168230` при этом был ПРАВИЛЬНЫЙ (вакансия есть в списке) — ломался только base.

**Фикс:** `HABR_API_BASE` → `https://career.habr.com/api/v1/integrations`. Все эндпоинты
(vacancies, responses, users, contacts) строятся от него → теперь бьют в живой API.

⚠️ Если на VPS в `.env` задан `HABR_API_BASE` — обновить и там (переопределяет дефолт).
После деплоя: повторить «Проверить отклики» — вместо 404 придёт 200 и отклики
импортируются (если на вакансии Хабра они есть; если нет — честный 0 без ошибки).
Схему ответа `/responses` (ключ `responses`) пиннить на первом реальном отклике по логам.
