# v1.7.10 — Хабр: фикс привязки по ссылке вместо id (отклики приходили 0) (2026-08-20)

Диагностика v1.7.9 сразу вскрыла причину «откликов 0»: в `habr_vacancy_id` была
записана **полная ссылка** `https://career.habr.com/vacancies/1000168230`, а не
числовой id. Клиент строит `{BASE}/vacancies/{id}/responses` → получался URL внутри
URL → Хабр отдавал HTML → «не-JSON ответ» → 0 откликов (ошибка глоталась в errors).

**Фикс:** `normalize_habr_vacancy_id(raw)` (client.py) достаёт числовой id из ссылки
(`vacancies/(\d+)`), чистый id оставляет как есть. Применяется:
- в `get_vacancy_responses` — терпит уже сохранённую ссылку, **старая привязка
  заработает без правки данных** (нормализация на лету при запросе);
- в `link_habr_vacancy` — новые привязки сохраняются чистым id.
- Юнит-тест `test_normalize_habr_vacancy_id` (ссылка/слэш/query/чистый id).

После деплоя: повторить «Проверить отклики» по Хабру — теперь API-URL корректный,
отклики импортируются. (Опц. очистить сохранённую ссылку в БД — не обязательно,
клиент нормализует на лету.)
