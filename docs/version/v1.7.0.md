# v1.7.0 — Импорт кандидатов из ATS Talantix (2026-08-15)

Миграция клиентской базы из Talantix (talantix.ru, GraphQL API, продукт hh):
кандидаты + резюме + **КОММЕНТАРИИ (главная ценность)** + согласие ПДн. По образцу
импорта из «Поток». Карточка Talantix в хабе импорта — из «Скоро» в рабочую.
⚠️ Сделано в ветке `feature/talantix-import` (в main НЕ мержится автоматически —
влитие/прогон миграции/pytest/пиннинг на живом токене за заказчиком).

- **Бэк:** `TalantixIntegration` (per-company Fernet, OAuth refresh с ротацией
  одноразового refresh_token). GraphQL-клиент (эндпоинт `api.talantix.ru/graphql`,
  `Bearer`, `data.errors→raise`, 401→refresh+retry, курсорная пагинация — история
  ВСЕ страницы). Union `PersonItem | PersonError` (PersonError не роняет импорт).
- **Импорт-джоб** (зеркало Потока): persons постранично → Candidate (source='talantix',
  дедуп телефон E.164/email, savepoint, `talantix_person_id`), резюме из
  `StructuredResume.skills` (плоский текст). Идемпотентно + докачка.
- ⚠️ **Комментарии:** `person.history` (все страницы курсора) → события
  `CommentAdded` (автор из `initiator`→CompanyManager) и `HhCommentAdded`
  (`managerName`) → `Comment(source='talantix', author_name_ext=автор ОРИГИНАЛА,
  created_at=дата ОРИГИНАЛА, external_id=id события)`. Автор/дата НЕ приписываются
  импортёру. Дедуп `(company_id, candidate_id, external_id)`.
- `personalDataAgreementStatus='agree'` → `Consent(signed)`. company_id ВЕЗДЕ. RBAC
  manager/hiring_manager → 403.
- **Фронт:** карточка Talantix (токен write-only → превью → импорт, хедлайн
  «Комментариев импортировано: N»); источник 'talantix' в фильтрах/цветах; пилюля
  «Talantix» у импортированного коммента.
- Миграция `c3e4f5a6b7c8` (← `a1c2e3f4b5d6`, одна голова). Схема Talantix сверена с
  рабочим клиентом проекта glafiraeuro + официальной докой.
- Адверс-ревью code-reviewer: **GO**, 0 блокеров; 1 HIGH (кросс-кандидатная потеря
  комментариев при person-scoped id события) — ПОЧИНЕН (candidate_id в ключ дедупа).
  Открытые предупреждения к решению перед merge: таймаут превью на большой базе,
  опциональный `access_token` (§0), refresh под in-process-локом.

**Пиннинг на живом токене Talantix (заказчик):** глобальность id событий истории;
`resumes.items[0].skills` = весь текст резюме; `personalDataAgreementStatus`;
типы контактов; скорость превью на большой базе. Прогон `pytest tests/test_talantix_import.py`.
