# v1.7.6 — Talantix: поддержка произвольных резюме CustomResume (2026-08-17)

Жалоба: часть кандидатов Talantix импортировалась с пустым резюме, хотя на Talantix
у них резюме есть.

**Причина (диагностирована пробингом):** у Talantix `resumes.items` бывают ДВУХ типов —
`StructuredResume` (структурное, разбирали с v1.7.3) и **`CustomResume`** (произвольное/
свёрстанное). Наш запрос разбирал только `StructuredResume` → для `CustomResume` не
запрашивали НИ ОДНОГО поля → пусто. `CustomResume = { name(заголовок), text(весь текст) }`.

- **Запрос** `PERSON_FULL_QUERY`: в `resumes.items` добавлен `__typename` +
  `... on CustomResume { name text }`.
- **Маппер** `_extract_resume` переписан под оба типа (различает по `__typename`):
  `StructuredResume` → структурный опыт/навыки/зарплата (как было); `CustomResume` →
  `name` → должность, `text` → текст резюме (структурного опыта у произвольного нет —
  не выдумываем, но текст и должность больше не теряем). Неизвестный тип → пусто (graceful).
- **Фронт** (`ResumeTab`): добавлен блок «Резюме» — показывает плоский `resume_text`,
  когда нет структурного опыта и нет отдельной сводки «Обо мне» (иначе произвольное
  резюме было бы не видно). `resume_text` уже отдаётся в детали кандидата.
- Тесты: мок резюме получил `__typename` (маппер теперь фильтрует по нему) + тест
  `CustomResume` (должность из name, текст из text, HTML снят, опыт пуст).

**⚠️ Заказчику на VPS после деплоя:** перезапустить бэкфилл
`python -m app.jobs.backfill_talantix_resumes` — теперь он подтянет текст произвольных
резюме тем, кто был пуст из-за CustomResume. Отдельно остаются ~374 транзиентно-упавших
на большом прогоне кандидата (не созданы) — их создаёт повторный импорт «Пропустить».
