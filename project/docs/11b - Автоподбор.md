# Экран 11b. «Умный подбор» → ветка В — **Автоподбор** (saved search)

> Третья ветка раздела «Умный подбор» (`/smart`). Открывается из **третьей карточки развилки** — «Автоподбор». URL ветки: `/smart/auto`.
> Это **автоматический сорсинг по сохранённым автопоискам hh.ru**. Аналог «Автопоиска» на hh: рекрутер один раз настроил фильтры и подписался — и новые подходящие резюме сами капают в поток. Глафира **забирает их, оценивает AI-матчингом сразу** и даёт открыть контакт / отправить в воронку или в пул.
> Статус — **beta**. Источник пока только hh.ru, поэтому рядом с заголовком — пилюля **«пока через hh»** (на будущее ветка обобщается на другие площадки).
> В прежнем ТЗ (экран 11) это было в списке «что осознанно НЕ в этом ТЗ»: *«Расписание/автозапуск активного поиска по новым резюме (saved search) — добавим позже»*. Этот документ закрывает тот пункт.

## Зачем это нужно

Ветка А (hh) — это **разовый** активный поиск под вакансию: запустил → получил выборку. Но сильные резюме появляются на hh **каждый день**, и каждый раз перезапускать поиск вручную — рутина. На hh для этого есть **автопоиск**: сохранённый набор фильтров + подписка; новые резюме помечаются как «+N новых».

«Автоподбор» переносит эту механику внутрь Глафиры и добавляет ценность сверху:
1. **Видим все сохранённые автопоиски hh** в одном месте, со счётчиком новых.
2. **Оцениваем поток автоматически**: для автопоиска можно включить авто-оценку, и каждое новое резюме приходит уже с AI-баллом.
3. **Действуем не выходя из Глафиры**: открыть контакт (списав 1 из пула hh), отправить кандидата в воронку вакансии или в свой пул.

> Ключевая идея механики hh: *«наставил фильтров, подписался — и кто попадает, того тебе показывают»*. Мы **забираем таких и оцениваем сразу**.

## Лейаут ветки

Двухколоночный (главный сайдбар + контент на всю ширину). Вверху — `‹ Выбор источника` (возврат на развилку). Три состояния идут одно из другого:

```
‹ Выбор источника
💃 Автоподбор  [beta]  [📡 пока через hh]                 [ 47 ]
Ваши автопоиски на hh.ru: фильтры настроены и подписаны…   контактов
                                                            в пуле
─────────────────────────────────────────────────────────────────
[ Список автопоисков ]  →  [ Кандидаты автопоиска ]  →  [ Карточка (снизу) ]
```

Шапка ветки всегда содержит **счётчик пула контактов** hh (сколько ещё резюме можно открыть) — справа, как в личном кабинете hh.

## Состояния ветки

| Состояние | Когда показывается |
|---|---|
| **Список автопоисков** | Вход в ветку: карточки сохранённых автопоисков hh |
| **Кандидаты автопоиска** | Клик по «Показать соискателей» / «Новые» в карточке автопоиска |
| **Карточка кандидата** | Клик по строке кандидата — выезжает **снизу** (bottom sheet) |
| **Диалог основы оценки** | При включении авто-оценки / клике «Оценить», если основа ещё не задана |

## 11b.1. Список автопоисков

Первый экран ветки. Шапка ветки (💃 + «Автоподбор» + beta + «пока через hh» + счётчик пула), под ней — панель и список карточек.

### Панель списка
- Слева: «Автопоиски» + счётчик + (если есть) `+N новых` (зелёная пилюля).
- Справа: статус синхронизации — `● синхронизировано с hh · обновляется раз в час` (зелёная точка).

### Карточка автопоиска
Карточка из двух частей: **основная** (слева) и **аside авто-оценки** (справа, на фоне-подложке).

**Основная часть:**
- Название автопоиска в кавычках («DevOps», «системный аналитик», «Business upgrade», «PHP-программист», «Laravel»…) + иконка-ссылка `↗` «Изменить автопоиск на hh».
- Регион 📍 (Новосибирск / Новосибирская область).
- Справа — дата обновления.
- **Чипы фильтров** (read-only сводка): `с переездом / без переезда` · `вкл. без ЗП / только с ЗП` · `за неделю / месяц`.
- **Тумблер-чип подписки**: `● подписка активна` (зелёный) / `● подписка выключена` (серый) — кликабельный. Подписка = присылать новые резюме в поток.
- **Низ карточки** — две ссылки-действия:
  - `Показать соискателей N` (синяя) — открыть **всех** соискателей автопоиска.
  - `● Новые +M` (зелёная) — открыть только **новые** с момента последнего просмотра; если новых нет — серое «новых нет».

**Аside «Авто-оценка новых»:**
- Заголовок «Авто-оценка новых» + подпись состояния: «новые приходят с AI-баллом» (вкл) / «оценивать вручную» (выкл) / «Глафира оценивает…» (идёт оценка).
- **Тумблер** авто-оценки.
- Если оценка включена/выполнена — **чип основы оценки** (см. 11b.4): `против вакансии «DevOps-инженер»` или `по промту «…»`, кликабелен (меняет основу).
- Во время прогона — `⟳ оцениваю новых…`.

> Включение тумблера авто-оценки, **если основа ещё не задана**, открывает диалог основы (11b.4). Это потому, что **оценка относительна** — без эталона (вакансия/промт) считать балл нельзя.

## 11b.2. Кандидаты автопоиска

Открывается по «Показать соискателей» / «Новые». Список спроектирован под **большой объём** (сотни-тысячи резюме) — плотные строки + пагинация.

### Хлебные крошки и основа
- `‹ Автопоиски` / «Название» · Регион.
- Справа в той же строке — **чип основы оценки** (если включена авто-оценка или поток оценён): `оценка против вакансии «…»` / `оценка по промту «…»`, кликабелен → диалог основы.

### Панель управления
- **Сегмент** `Все N` / `● Новые M` (переключение всего списка; «Новые» недоступны, если их нет).
- **Сортировка**: «по обновлению» / «по AI-баллу» (последняя доступна только когда поток оценён).
- **Инлайн-тумблер** «Авто-оценка новых».
- **Кнопка `✨ Оценить N`** (если поток ещё не оценён) — запускает разовую оценку всего среза. Если основа не задана — сначала диалог основы (11b.4).
- Под панелью, в режиме «Новые», — нотис: «Показаны только новые с момента последнего просмотра. Открытие списка сбрасывает счётчик «+M» на hh».

### Строка кандидата (плотная)
На **бесплатных полях** hh (контакты закрыты):
- **Аватар-заглушка** (контакты закрыты → силуэт); у новых — зелёная точка-пип.
- Должность (заголовок резюме) · возраст · город · (если анонимное) чип `🔒 аноним`.
- Последнее место: должность · компания · опыт.
- **Чипы навыков** (до 5 + «+N»).
- Справа: зарплатные ожидания (или «з/п не указана») + «обновлено …».
- **AI-балл**: бейдж скоринга, если поток оценён; иначе `—` (пунктирная заглушка «не оценён»).
- Если кандидат уже забран — флажок `✓ в пуле / в воронке` в углу.
- Левый край строки у новых — зелёная полоса (акцент «новое»).
- Клик по строке — открывает **карточку снизу** (11b.3).

### Пагинация
- По **10 кандидатов** на страницу.
- **Windowed-пейджер**: `‹ 1 … 4 5 6 … 65 ›`; активная страница — акцентная; стрелки назад/вперёд; многоточия для скрытых диапазонов.
- Над пейджером — «Показано 11–20 из 650».
- Глубина выдачи ограничена (как на hh, ≤ 2000).
- Смена страницы/сегмента/сортировки подкручивает список к началу; смена сегмента/сортировки сбрасывает на страницу 1.

## 11b.3. Карточка кандидата (bottom sheet) — **1:1 с карточкой соискателя**

Открывается **снизу** (выезжающий лист). Внутри — **тот же компонент, что карточка соискателя на экране 4** (`.cand-detail`): те же классы, верстка, табы, блоки. Никакого отдельного дизайна — только контекст Автоподбора в действиях и в состоянии контактов.

Закрытие: крестик в тулбаре, клик по затемнению, `Esc`.

### Тулбар (действия Автоподбора, кнопки общей системы)
- `↗ Забрать контакт` (primary) — **если контакт ещё не открыт**. Списывает 1 контакт из пула hh.
- `→ Перевести ▾` (success) — поповер «Куда перенести кандидата?»:
  - **`В пул кандидатов`** (иконка 👥).
  - Группа «В воронку вакансии» — список всех открытых вакансий (название + счётчик), как в карточке соискателя (`cd-move-pop`).
  - Текущее назначение помечается «сейчас». После перевода кнопка показывает `В пуле` / `В воронке`.
- `✓ Контакт открыт` — зелёный чип-подтверждение, когда контакт уже списан.
- Крестик закрытия — справа.

> Перевод **требует контакта**: если контакт ещё не открыт, перевод **сам списывает 1 из пула** (и открывает контакт), затем переносит.

### Шапка (`cd-header`)
- Контекст: пилюля источника `hh · Автопоиск «…»` · «обновлено …» · регион.
- Имя: **должность резюме** (пока контакт закрыт) → **ФИО** (после открытия). Рядом — AI-бейдж (если оценён) и пилюля `● новое`.
- Строка опыта: должность · компания · опыт.
- Зарплата: ожидания (или «з/п не указана»).
- Теги: чипы ключевых навыков (4 шт).
- **Блок контактов** (`cd-contact-box`):
  - **Закрыт** (по умолчанию): `Контакты: 🔒 закрыты на hh`, телефон-маска `+7 ••• ••• •• ••`, город; сноска «Откроется после списания 1 контакта из пула (осталось N)». Для анонимного — предупреждение «Резюме анонимное — ФИО и телефон могут не прийти».
  - **Открыт**: реальный телефон (+ иконки мессенджеров tg/wa), город, e-mail — как в обычной карточке.

### Табы (`cc-tabs`)
Только два (остальные табы соискателя — чат/звонки/документы — в этом контексте не нужны):
- **Резюме**
- **Оценка AI**

### Таб «Резюме» (`resume-single`)
- Если оценён — **карточка вердикта Глафиры** (`filo-card`, 👩🏻 + короткий вердикт + AI-бейдж). Если не оценён — нотис «откройте вкладку Оценка AI, чтобы сравнить с вакансией или промтом».
- **Опыт работы** — блоки `job` (период/длительность + компания + должность + буллеты), как в карточке соискателя.
- **Навыки** — `skill-chip`.
- **Образование** — блок `job`.
- **Дополнительно** — `extra-grid` (языки, переезд, город, источник = hh.ru · автопоиск).

### Таб «Оценка AI» (`ai-single`)
- Если **не оценён** — пустое состояние: иконка ✨, «Резюме ещё не оценено», пояснение что **оценка относительна** (нужна вакансия/промт), кнопка `✨ Оценить относительно…`.
- Если оценён:
  - **Вердикт-скрининг** (`filo-card` showScreening): «Сравнила резюме **с вакансией «…»** / **с запросом «…»**. Совпадение с требованиями — N%. Опыт …, ожидания … ₽.» — т.е. **в явном виде ссылается на основу оценки**.
  - **Анализ AI**: блоки `✅ Сильные стороны`, `⚠️ Слабые стороны`, `💬 Вопросы для первого контакта` (`msg ai-msg …`).
  - **Разбор по критериям** (`crit-list`): релевантность позиции, опыт и стаж, совпадение навыков, регион/переезд, зарплатные ожидания — у каждого балл/макс, прогресс-бар (зелёный/жёлтый/красный) и комментарий. Сверху — суммарный балл `pts / max`.

## 11b.4. Диалог «Относительно чего оценивать?» (основа оценки)

Ключевой принцип: **оценка кандидата — относительная**. Балл не имеет смысла без эталона. Поэтому **перед первой оценкой** автопоиска (включение авто-оценки или клик «Оценить») Глафира спрашивает основу.

Модальное окно по центру:
- Заголовок «Относительно чего оценивать?» + пояснение «Оценка кандидата — относительная. Глафира сравнит резюме из автопоиска «…» с вашей вакансией или с описанием идеального кандидата.»
- **Метод 1 — По открытой вакансии** (по умолчанию): радио + список всех открытых вакансий (название + счётчик, выбор галочкой). Глафира берёт требования вакансии как эталон.
- Разделитель **«или»**.
- **Метод 2 — По описанию (промт)**: радио + textarea «опишите, кто нужен» (станет эталоном).
- Низ: `Отмена` · `✨ Включить авто-оценку` / `✨ Оценить` (по контексту вызова). Кнопка неактивна, пока не выбрана вакансия / не введён промт (≥3 симв.).

После подтверждения основа сохраняется на автопоиск, запускается оценка, а основа показывается чипом (в списке и над списком кандидатов) и **в карточке кандидата** (вердикт AI ссылается на неё). Чип кликабелен — основу можно сменить в любой момент (повторный диалог, кнопка `Оценить`/`Включить` соответственно).

Дефолтная основа для предвключённых автопоисков: «DevOps» → вакансия «DevOps-инженер», «системный аналитик» → вакансия «Системный аналитик».

## 11b.5. Пул контактов

Открытие контакта стоит **1 контакт из пула** hh (счётчик в шапке ветки).
- Забрать контакт / перевести непросмотренного — списывает 1, контакт раскрывается (телефон, мессенджеры, e-mail).
- Повторные действия по уже открытому кандидату контакт **не** списывают.
- **Анонимное резюме**: контакт всё равно списывается, но ФИО/телефон могут не прийти — об этом предупреждаем заранее.
- **Пул исчерпан** (0): действие блокируется, тост «Пул контактов исчерпан. Пополните в кабинете hh».

## Поведение и связи

- **Перевод в воронку** добавляет кандидата в воронку выбранной вакансии (экран 3) и в общую базу (экран 5) с источником «Автоподбор / hh.ru». Тост с действием `Открыть воронку`.
- **Перевод в пул** добавляет кандидата в общую базу (экран 5). Тост с действием `Открыть базу`.
- **Изменить автопоиск** (`↗`) — ведёт в личный кабинет hh (там живут сами фильтры/подписки).
- Карточка кандидата переиспользует компонент карточки соискателя (экран 4) → единый дизайн и поведение.
- Источник данных строк — **бесплатные поля** hh (должность, опыт, навыки, город, ожидания); ФИО/контакты закрыты до списания.

## Тестовые стейты (Tweaks)

| Тумблер / кнопка | Назначение |
|---|---|
| **Открыть Автоподбор** | Быстрый переход сразу в ветку (минуя развилку) |
| **Показать (presetView)** | значение `Автоподбор · автопоиски hh` открывает ветку по умолчанию |

## Edge cases

- **Новых нет** → ссылка «Новые» серая («новых нет»); сегмент «Новые» в списке кандидатов недоступен.
- **Поток не оценён** → AI-балл в строках `—`; сортировка «по AI-баллу» недоступна; в карточке таб «Оценка AI» показывает пустое состояние с CTA.
- **Включение авто-оценки/Оценить без основы** → диалог основы (11b.4), без него оценка не стартует.
- **Пул исчерпан** → действия с контактом блокируются с тостом.
- **Анонимное резюме** → чип `аноним` в строке + предупреждение в карточке; ФИО/телефон могут не открыться.
- **Маленький автопоиск** (например, 11 резюме) → пагинация корректно схлопывается (2 страницы), последняя страница может содержать 1 строку.
- **Длинные названия** (автопоиска/вакансии/навыка) → эллипсис.

## Модель данных (для реализации)

**Saved search (автопоиск):**
```
{ id, name, region, period, total, newCount,
  subscribed: bool, autoEval: bool,
  filters: { relocate: bool, includeNoSalary: bool },
  basis: { kind: 'vacancy'|'prompt', vacancyId?, prompt? } | null,
  updatedAt }
```

**Кандидат автопоиска (бесплатные поля):**
```
{ id, searchId, title, age, city, anonymous: bool,
  salary | null, experience, skills[],
  jobs[], education, updatedAt, isNew: bool,
  score | null,                  // появляется после оценки относительно basis
  contact: { opened: bool, name?, phone?, email?, messengers? } }
```

**Пул:** `pool.contactsLeft` (списывается при открытии контакта).
