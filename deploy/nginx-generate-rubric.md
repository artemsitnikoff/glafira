# nginx: таймаут для «Сгенерировать критерии» (генерация рубрикатора вакансии)

Кнопка «Сгенерировать критерии» в форме вакансии ждёт ответ LLM **синхронно**. С v1.4.1
бекенд ждёт до **110 секунд** (`api/v1/vacancies.py`, `asyncio.wait_for(..., timeout=110)`;
httpx read = 120с). Но по умолчанию общий **nginx оборвёт запрос ~на 60-й секунде с 504**,
и 110с бекенда не сработают. Поэтому у location Глафиры, проксирующего `/api/`, нужно поднять
`proxy_read_timeout`.

⚠️ nginx на VPS **общий** (там сервисы других проектов) — правим ТОЛЬКО server-блок Глафиры
(`server_name glafira.dclouds.ru`), чужие не трогаем. `nginx -t` перед reload.

## Что сделать (РУКАМИ на VPS, один раз)

В конфиге nginx Глафиры (обычно `/etc/nginx/sites-available/glafira*` или в общем
`nginx.conf` — найти по `server_name glafira.dclouds.ru`), в блоке `location`, который
проксирует API на бекенд (`proxy_pass` на порт бекенда, напр. `127.0.0.1:8000`), добавить/
поднять таймауты:

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8000;   # ← как уже есть, порт не менять
    # ... существующие proxy_set_header X-Forwarded-Proto $scheme и пр. — НЕ трогать ...

    proxy_read_timeout  120s;   # было ~60s (дефолт) → генерация рубрикатора успевает
    proxy_send_timeout  120s;
}
```

Если отдельного `location /api/` нет (проксируется общий `location /`), добавить эти две
строки туда же (120s — это МАКСИМУМ ожидания, обычные быстрые запросы он не замедляет).

Применить:
```bash
sudo nginx -t && sudo systemctl reload nginx
```

## Проверка
Форма вакансии → «Сгенерировать критерии» на «тяжёлой» модели: теперь укладывается в 110с,
а не обрывается на ~50–60. Если конкретная модель всё равно не успевает за 110с — она реально
очень медленная, выбрать быстрее в Настройки → AI (сообщение об этом остаётся честным).
